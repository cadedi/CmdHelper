## 🌟 核心特性

1. **需求驱动（按“解决什么问题”检索）**：
   - 摆脱死记硬背枯燥繁杂的命令选项，完全按实际业务运维场景组织。
   - 涵盖 **Linux 运维、SQL 数据库、Docker & K8s、Redis 缓存、Git 版本控制、Nginx 网关、PowerShell、文件归档、文本与日志、网络与端口** 等多维场景。

2. **智能参数表单 & 毫秒级动态实时拼接**：
   - 自动解析命令参数类型（文本输入、预设下拉选项、可选功能复选框）。
   - 用户在界面修改任何输入框或选项时，命令展示区**毫秒级动态实时计算拼接**，所见即所得。
   - 带有高危操作提示（如删除数据、强制杀进程、强制覆盖分支等）。

3. **跨平台支持 (Linux / Windows / macOS / Web 全覆盖)**：
   - **Linux 原生单文件 ELF (`CmdHelper-linux-x64`)**：
     - 基于 **.NET 8 + Avalonia UI 11** 构建，自带独立运行库。
     - 在任何主流 Linux 发行版（Ubuntu、CentOS、Debian、统信 UOS、银河麒麟）上，只需 `chmod +x` 双击即可原生运行，**无需目标机预装 .NET 运行时**！
   - **Windows 极轻量原生版 (`CmdHelper.exe`)**：
     - 专精 Windows Server 2016+ / Win10 / Win11，单文件仅 **1.1 MB**，开箱即用免装环境。
   - **单文件离线网页版 (`CmdHelper_Web.html`)**：
     - 零 CDN 外部网络依赖，100% 自包含，物理隔离内网/堡垒机浏览器秒开。

4. **i18n 国际化多语言即时切换**：
   - 支持 **简体中文 (`zh-CN`)** 与 **English (`en-US`)** 一键即时切换。
   - 涵盖顶部工具栏、分类名智能映射（如 `Linux 运维` $\leftrightarrow$ `Linux Operations`）、参数标签、徽章及数据源弹窗全部文案。

5. **深色 / 浅色模式（Dark & Light Theme）平滑换肤**：
   - **浅色模式**：高对比度 `#EEEEEE` 护眼背景，层次分明，字迹饱满清晰；
   - **深色模式**：现代深灰/黑曜石暗色质感主题；
   - 顶部工具栏提供 `🌓 主题切换` 按钮，自动持久化记忆用户偏好。

6. **多数据源配置 & 远程 API 接口同步 & 按 ID 智能去重**：
   - 支持配置多个远程 HTTP/HTTPS API 或本地 JSON 文件；
   - 智能按命令 `id` 覆盖更新旧项或追加新增；
   - 支持接口返回格式自动拆包与离线双层本地缓存。

7. **从客户端一键导出单文件 Web 版 HTML**：
   - 支持在客户端内一键将当前全量（含远程同步后）的命令库打包导出为独立的单文件 HTML，实现任意设备的脱机流转。

## 🚀 快速使用指南

### 1. Linux 平台 (Ubuntu / CentOS / Debian / 银河麒麟 / 统信 UOS)
```bash
# 赋予执行权限并直接运行单文件 ELF 程序
chmod +x ./CmdHelper-linux-x64

```

### 2. Windows 平台
- **通用现代环境 (推荐)**：直接双击 `release/CmdHelper-win-x64.exe`（支持多语言与深浅主题切换）。
- **Windows Server 2016 / 极轻量便携**：直接双击 `release/CmdHelper.exe`（仅 1.1 MB，免安装任何运行库）。

### 3. 跨平台纯单文件离线 Web 版
直接双击 `release/CmdHelper_Web.html` 即可在 Edge、Chrome、Firefox 等任何浏览器中离线使用。

## 📡 多数据源配置 & 远程 API 接口同步

程序现已原生支持配置**多个外部数据源**（可以是公司内网 API、云端 REST 接口、GitHub/GitLab Raw 链接或本地 `.json` 文件）：

### 1. 数据加载与合并策略
- **智能去重合并 (`merge`)**：
  - 以命令对象的 `id` 字段作为唯一主键；
  - 若远程接口返回的命令 `id` 在当前库中已存在，则**自动以远程最新内容更新覆盖旧项**；
  - 若 `id` 不存在，则**自动追加新增**为新场景卡片；
- **完全替代覆盖 (`replace`)**：
  - 彻底清空已有命令库，完全以该远程接口的数据为准；

### 2. 接口返回格式智能兼容
程序兼容常见的多种 JSON 格式，无论接口直接返回数组还是包含通用包装层，均能自动解包识别：
- 直接数组：`[ { "id": "...", "title": "..." }, ... ]`
- 常见后端包装：`{ "code": 200, "data": [ { ... } ] }`
- 分页/列表包装：`{ "data": { "list": [ { ... } ] } }` 或 `{ "result": [ { ... } ] }`

### 3. 离线容错与双层缓存机制
- 当首次成功从远程接口拉取数据后，客户端会自动将数据缓存至本地（EXE 版保存为 `cache_{id}.json`，Web 版保存至 `localStorage`）；
- 若在离线、断网或内网隔离机上再次启动程序，会自动加载上次的离线缓存，**绝不阻塞界面，也无需担心断网不可用**！

## ❓ 常见问题解答 (FAQ)

### Q1：后续运行程序，需要携带什么？
**只需携带单个可执行文件即可！**
默认的全量命令库已作为嵌入资源直接打包进程序内部，无需附带 `commands.json`，随时拷贝到 U 盘或服务器上独立运行。

---

### Q2：如果要添加或修改命令，必须重新编译吗？
**不需要重新编译！支持以下多种免编译扩展方式：**
1. **外部文件即时覆盖**：在程序所在目录下放置同名 `commands.json`，程序启动时会自动优先加载外部文件；
2. **多数据源/远程接口同步**：在界面右上角点击“📡 数据源配置”，填入内网 JSON 接口或 Git raw 链接即可一键拉取合并；
3. **临时追加命令**：在程序同级目录下新建 `custom_commands.json`，程序会自动增量合并到现有列表中。

---

### Q3：HTML 网页版是否依赖 CDN？
**完全不依赖任何 CDN！**
页面采用 100% 原生自包含设计，所有图标均为内联矢量 SVG，字体使用系统本地字体栈，能够在物理隔离的机房内网、涉密网和离线堡垒机中完美运行。
